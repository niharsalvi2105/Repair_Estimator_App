## Cost previews

Sources: [packageCosts](../src/data/packageCosts.ts), [EstimatorWorkspace](../src/EstimatorWorkspace.tsx#L244-L252), [package amount UI](../src/PackageCostDetails.tsx), [per-equipment UI](../src/EquipmentPackageCosts.tsx), [rate repository](../src/data/repairEstimatorRepository.ts), [assignment helpers](../src/data/packageEquipment.ts).

| Output | Browser formula |
|---|---|
| Predefined package | `Q = number of selected equipment applicable to package`; `Hours = hours/unit * Q`, `Labor = Hours * rate`, `Material = material/unit * Q`, `Total = Labor + Material*(1+taxPct/100+freightPct/100)`. Rates match exactly on role/time. For standard, tax/freight are 5/14; ordinary custom uses entered rates; package-priced KONE uses before-markup cost and 0/0. Per-unit standard uses `Q=1`. |
| CSTM combined package | Add `sum(line hours)` to package hours, `sum(line hours * (saved rate ?? matching branch/role/time rate))` to labor, `sum(quantity * unit cost)` to material, and `custom labor + custom material*(1+taxPct/100+freightPct/100)` to predefined total. Needs at least one valid CSTM line. Separate KONE final display = final material/unit times `Q`. |
| Equipment-specific CSTM | Begin with one unit of predefined cost. Share of each custom line = `1/Q` if shared, `1` for the matching equipment, else `0`. Add share-weighted hours, labor and raw material; tax/freight = predefined unit amounts plus share-weighted custom material times respective rates. Total = labor + all unit material + tax + freight. Effective rate = labor/hours if hours positive, else base rate. |
| Average CSTM unit | Combined hours, labor, material, and total each divided by `Q`; `rate = total labor/total hours` if positive hours, else base rate. Predefined unit tax/freight plus `custom material * respective rate / 100 / Q`. The displayed tax/freight rates switch to the custom rates if custom material is positive. |
| Additional preview | `additional labor hours * mechanic rate + (additional material + miscellaneous)*(1+taxPct/100+freightPct/100)`. Tax and freight individually multiply that material-plus-miscellaneous base. Package subtotal is the sum of package previews; combined preview adds separately calculated additions once. |

The [custom line editor](../src/CustomCostLines.tsx) sums visible raw material `quantity*unitCost` without tax/freight ([customMaterialCosts](../src/data/customMaterialCosts.ts)) and sums visible labor hours. Its labor cost preview sums **per-line** amounts rounded as `Math.round((hours*rate + EPSILON*max(1,hours*rate))*100)/100`; unavailable rates prevent a complete total ([laborGrid](../src/data/laborGrid.ts)). That is distinct from the unrounded CSTM package preview and server decimal rounding. [Equipment display](../src/data/equipmentDisplay.ts) uses a valid explicit age, else current local year minus a valid positive integer construction year not in the future; otherwise no age. Dataverse saves the age snapshot.

**Dev-only material prototype:** [partMaterials](../src/data/partMaterials.ts) and [MaterialCatalogPreview](../src/dev/MaterialCatalogPreview.tsx) are not the authoritative catalog route. Prototype catalog cost is `USD cost per unit * costFactor * FX`; prototype catalog price is `USD price for the whole pricing unit * FX / pricingUnit`. Both factors are 1 for MKO. Raw material = quantity times unit cost; landed = raw times `(1+(materialTax+materialFreight)/100)`; KONE markup = quantity times unit price times markup percent/100; KONE selling contribution = quantity times unit price times `(1+(koneTax+koneFreight+markup)/100)`. The demo also illustrates separate manual cost times `1.19` and combines package + additional + that amount; these are not production formulas.

## Billing, pricing display, and dashboard

* [Billing preview](../src/data/billingPayments.ts) and [choice mapping](../src/RequestFields.tsx#L71-L140): `126110000 → 50%`, `126110001 → 60%`, `126110002 → 0%`, `126110003 → notes only`. `cents = Math.round(Number(sell.toFixed(2))*100)`; `depositCents = Math.round(cents*depositPct/100)`; down payment = `depositCents/100`; final = `(cents-depositCents)/100`. Holding the remainder makes the displayed payments sum to the cent-rounded sell. This is not a second selling-price engine and isn't the same rule as the server's billing-plan threshold.
* [Pricing summary](../src/PricingSummary.tsx) consumes [saved Dataverse data](../src/data/pricingRepository.ts). The [cost chart](../src/data/pricingPresentation.ts) converts saved package total, custom labor, custom material, total additional and true cost to cents with `Math.round(value*100)`. `other = additional - custom labor - custom material`. Hide if a source is absent, invalid/negative, other is negative, or `abs(package + additional - true cost) > 1 cent`. Segments are package, custom labor, custom material and other; segment amount is cents/100 and share is segment cents/(package+additional), or zero when denominator zero. Other includes amounts such as tax/freight not already in the custom material base; it is not an extra cost. Gauge clamps actual to `[0,1]` for the drawn arc only; text displays actual. Variance text is fraction times 100 in percentage points.
* [DashboardReader](../backend/DashboardReader.cs#L44-L103) counts active, market-filtered, all-time estimates, with owner filter for non-Admin. Total = sum of status counts; independent sum of grouped job-type counts must match. Average CMII = arithmetic `sum(saved actual CMII)/eligible count`: requires non-null actual, positive sell, timestamp, and a non-null version other than `unavailable`. Zero eligible → no average. It is not weighted by selling price and does not exclude negative outliers. [Dashboard components](../src/DashboardMetrics.tsx) plot selected status indices 0 and 2 as share of their combined count; arc length is `100*status count/chart total`, remainder is `100 - arc length` and offset is `-100*preceding plotted count/chart total`. Job-type percentage = group count/all scoped requests; list sorted by descending count. Data contract also checks grouped totals ([dashboardContract](../src/data/dashboardContract.ts)).

## Excel input, workbook output and email

| Layer | Calculation or dependency |
|---|---|
| Excel import | [Custom costs import](../src/data/customCostExcel.ts) scales numeric cells by 100, compares distance to nearest integer using tolerance `2*Number.EPSILON*max(1,abs(scaled))`, rejects excess precision, and normalizes accepted values to `Math.round(scaled)/100`. Imported quantities, hours and cost use the same draft calculation path; Excel is not the estimate pricing engine. [Equipment import](../src/data/equipmentExcel.ts) affects selected equipment and therefore package quantity; no independent pricing formula. |
| Upstream source ingestion | [MKO parts](../automation/import-mko-parts.py) can quantize numeric mapped inputs to six decimals, half up when requested, and converts Excel serial dates from `1899-12-30 + integer days`. [MKO equipment](../automation/import-mko-equipment.py) quantizes selected source decimal fields to eight places, half up. These transformations precede reference-table loading; neither calculates the estimate. |
| Queued export | [ExportRequestPlugin](../backend-pricing/Automation/ExportRequestPlugin.cs#L112-L192) loads, calculates and validates with the same server engine; [ExportSnapshot](../backend-pricing/Automation/ExportSnapshot.cs) freezes header and child values, plus IDs/version, and hashes the serialized payload. Export finalization preserves frozen values rather than recalculating prices. |
| Workbook renderers | [FillEstimate](../automation/office-scripts/FillEstimate.ts) and [FillSubmission](../automation/office-scripts/FillSubmission.ts) write snapshot values into the templates built by [build-templates](../automation/build-templates.cjs) and [build-submission-template](../automation/build-submission-template.cjs). `FillSubmission` converts variance to `variance*100` for percentage points, while percent-formatted fraction fields stay fractions. `FillEstimate` maps labor into role/time columns with zero-based column `12 + 2*(roleChoice-126110000) + (timeChoice-126110000)`; summary overflow = count minus displayed cap (14 equipment, 3 packages), with detail retained. These renderers do not independently run the PST calculator. |
| Email header | [Flow generator](../automation/build-estimate-email-flow.mjs#L207-L236) formats saved money and fractional percentages (`value*100`, then `%`); raw itemized markup already uses percentage points. Billing converts selling price to cents via `int(formatNumber(sell*100,'0','en-US'))`; deposit cents = integer division `(cents*depositPct + 50)/100`, balance = `(cents-depositCents)/100`, deposit = `depositCents/100`. Uses the same 50/60/0 choices, with notes for custom. |
| Email package rows | [Flow per-package expressions](../automation/build-estimate-email-flow.mjs#L272-L345) filter children by saved parent package. Display hours = saved `re_totalhours + sum(child hours)`; labor = saved package hours times saved estimate mechanic rate + sum child `re_totalcost`; material = saved package `re_totalmaterial + sum(child re_extendedcost)`. Package estimated row = predefined labor + `re_totalmaterial*(1+packageTax+packageFreight)` + sum child labor totals + sum child material totals. Tax/freight = 0/0 for package-priced KONE, 5%/14% for standard, saved estimate fractions for ordinary custom. KONE final display = `re_materialcostperunit*re_quantity`. Empty child sums are zero. |

**Reconciliation caveats:** Email package rows use saved package quantity and rounded child totals, so they need not add up exactly to the engine header total; they also exclude estimate-level additions. Generated email material selling price requires a catalog lookup and positive stored catalog price before displaying an override/price, so an entered manual KONE selling price can appear as not applicable in that email field even though engine pricing uses it. Dashboard CMII and display ratios are reporting outputs, not additional pricing rules.
