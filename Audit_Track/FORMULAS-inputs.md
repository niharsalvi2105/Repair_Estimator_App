## Input lineage and precedence

Source: [EstimateInputLoader](../backend-pricing/Data/EstimateInputLoader.cs#L25-L336), [ReferenceData](../backend-pricing/Data/ReferenceData.cs#L41-L162), [Dataverse logical names](../backend-pricing/Infrastructure/Names.cs), [query rules](../backend-pricing/Data/Query.cs#L35-L51).

| Dependency | Input and selection |
|---|---|
| Estimate and branch | `re_repairestimate` supplies entered sell price, stated rate, additional inputs, VK13 aggregate, billing choice, comment and situational choices. Absent numeric estimate inputs read as zero for the engine. `re_branch` supplies margin group and fallback country/province. Create defaults include revision 1, initiating salesperson, and missing country/currency/market/province from branch ([EstimateDefaults](../backend-pricing/Plugins/EstimateDefaults.cs)). |
| Tax and freight | Resolve separately: estimate `re_usetax` / `re_freight` → respective estimate percentage aliases → `re_stateprovince` defaults → branch defaults → `DEFAULT_USE_TAX` / `DEFAULT_FREIGHT`. Building province precedes branch province. An explicit zero takes precedence. Draft save divides percent input by 100; draft read multiplies back by 100; engine writes both aliases as fractions. |
| Estimate package/additional labor | `re_laborrate` exact branch + Mechanic + **estimate-level** time category; exactly one active effective row with `re_hourlycost`, not simply the most recent of duplicates. |
| Custom labor | Exact branch + **line** role and time, active and effective; new snapshot requires exactly one nonnegative rate. Unchanged existing role/time with saved rate and lookup retains the snapshot. `re_hourlycost = R2(master rate)`; `re_totalcost = R2(hours * saved hourly cost)`; engine sums from hours and rates, not from already rounded child totals. |
| Equipment and redundancy | Active `re_estimateequipment` lines counted. Additional equipment text contributes the number of nonempty comma-separated tokens (no dedup); blank or leading `***` after left trim gives zero. Primary = flagged row, else first by sequence (null sequences last). OEM and age come from its snapshot. A resolved `re_equipment` master requires a nonblank snapshot functional location; redundancy = `max(1, count of active equipment masters with that exact location)`, otherwise default 1. |
| Vertical, job, fixed target | `re_customervertical` estimate lookup first, else first active match of the primary snapshot's vertical code. `re_jobtype` supplies rating; `re_equipmenttype` supplies fixed target CMII. |
| Package | `re_repairpackage` supplies predefined per-unit hours and material; `re_estimatepackage` retains the corresponding snapshots. Engine custom path if a saved package is custom or the estimate path resolves to custom. The draft save itself requires a CSTM package to save custom lines or positive aggregate spares sale. |
| Bands and adjustment | `re_jobsizeband`, `re_oembandrule`, `re_redundancyband`, `re_bandmatrix`, `re_situationaladjustment`. `re_marginrule` is restricted to estimate branch's margin group and effective date. |
| Parameters and incentives | `re_pricingparameter`: case-insensitive code; choose country row over global row (not field-by-field); duplicate country/code fails. Country is estimate first, then branch. `re_incentiverate`: all country rows if any, else all global rows; no threshold-level mixing. |

Reference date is UTC day. Effective-date pricing queries require active rows, `effectiveFrom <= date`, and blank `effectiveTo` or `effectiveTo >= date`. Dataverse choices resolve through [OptionMap](../backend-pricing/Infrastructure/OptionMap.cs); the business labels, not arbitrary UI indexes, drive engine comparisons. The full parameter code list is in [PricingModels](../backend-pricing/Pricing/PricingModels.cs#L49-L64); the effect of every code is documented in the server and input tables. Required numeric parameters throw if requested and absent; OEM default text has a Low fallback. Actual rates, thresholds, payout rows and band matrices are tenant data, not constants in this reference.

## Package and child snapshots

Source: [DraftPlugin package save](../backend/DraftPlugin.cs#L503-L610), [line save](../backend/DraftPlugin.cs#L800-L906), [equipment subset validation](../backend-pricing/Infrastructure/PackageEquipmentSnapshot.cs), [material route enforcement](../backend/PackageMaterialPricing.cs).

* Saved package `re_quantity = explicit assignment count ?? selected equipment count`; assignments are validated as an actual subset, not supplied as an independent multiplier. `re_totalhours = re_mechanichoursperunit * re_quantity`. `re_totalmaterial = re_quantity * (re_materialbeforemarkup if package-priced KONE, otherwise re_materialcostperunit)`. **Engine fallback differs:** when no subset is saved, its quantity is the header `N` (includes valid additional-equipment tokens); saved package/email/UI quantity need not.
* Package-priced KONE snapshots hold both the true material before markup and final material from `re_materialmisctaxcost`. A reference line is linked to that package and cost is zero; it identifies the route rather than adding material. No second charge for that reference. A tagged KONE reference without matching eligible package (or eligible package without reference) fails. The activation path checks package validity and branch country/currency compatibility.
* Child material `re_unitcost = R2(effective unit cost)`; raw extended `E = quantity * effective unit cost`; saved `re_extendedcost = R2(E)`, `re_taxamount = R2(E*t)`, `re_freightamount = R2(E*f)`, `re_totalcost = R2(E*(1+t+f))`. The draft writer uses header tax/freight and sets both applicability flags except for zero-cost package references. The engine can honor independent saved flags and uses precise unit cost where present. The displayed unit cost times quantity can differ from extended cost, and summing rounded child totals is not the engine total.
* Draft quantity is whole `1..100000`; custom labor hours are positive up to `100000`, at most two decimals. Noncatalog entered unit cost is positive up to `1,000,000,000`, at most two decimals on draft save. Selling-price override is positive up to `1,000,000,000`, up to ten decimal places. These are validity checks, not rounding the user's invalid input into an accepted value.

## Catalog, manual and legacy paths

Source: [PartCatalog](../backend/PartCatalog.cs#L88-L180), [server conversion and snapshot](../backend/PartCatalog.cs#L236-L358), [material pricing input construction](../backend-pricing/Data/EstimateInputLoader.cs#L227-L302), [schema](../backend/parts-catalog-schema.json).

| Route | Formula inputs |
|---|---|
| Approved catalog | Active effective `re_sparepart`, USD source, pricing unit exactly 1, source cost and VK13 price up to six decimal places; provenance includes source key, version and refresh date. Active effective market/currency configuration in `re_partpricingconfiguration`. MKO has `fx = uplift = 1`, others use `re_usdtocadfactor` and `re_costonlyfactor`. **Both** `convertedUnitCost = sourceCost * fx * uplift` and `convertedUnitPrice = sourcePrice * fx * uplift` in this server implementation. Converted values must meet amount bounds and fit ten decimal places; invalid values are flagged, not silently rounded. Catalog selection retains its saved source/configuration snapshot until reselected. Allowed explicit estimate-only replacements do not update catalog master values. |
| Catalog price precedence | Loader uses `re_unitcostprecise ?? re_unitcost` and `re_sellingprice ?? re_unitpriceprecise`. A catalog lookup and positive effective price qualify and remain part of the snapshot for diagnostics/export. KONE uses the itemized selling rule. Since pricing 2026.13, Non-KONE suggested price uses landed cost with the configured material margin floor/target rule, not catalog or entered selling price. |
| Manual KONE (current local source) | No catalog ID or VK13 price; uses entered unit cost plus entered unit selling price, explicit KONE/manual type and fixed `re_markuppct = 10`. `10% * quantity * entered unit selling price` is the markup component, not a division by `1 - .10`. Changing selling price alone does not change true cost. |
| Manual Non-KONE | Entered unit cost and quantity produce material cost; no catalog-selling substitution or KONE markup. |
| Legacy / package | Legacy material with no explicit classification can use vendor/part heuristics for cost classification; legacy aggregate VK13 is entered at the estimate level. Package-priced KONE separates final selling package amount from true material before markup; neither route may be combined with conflicting itemized KONE. |

Equipment age UI default is documented in [browser formulas](FORMULAS-display-export.md); the engine does not recompute time-based age from construction year at price time. Cloning is not an arithmetic path: copied choices/snapshots and cleared fields, including reset selling price and optional omission of custom costs, feed the same engine on the new estimate ([requestClone](../src/data/requestClone.ts), [cloneValidation](../src/data/cloneValidation.ts)).
